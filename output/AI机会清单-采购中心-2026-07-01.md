## 一、采购中心流程概览

采购中心承接全公司 5+ 部门（装备研发、电池研发、产线策划、生产交付、AI 3D 事业中心）的物料/设备采购需求。完整流程 11 个节点：

```
需求接收 → 供应商匹配/寻源 → 询价/比价 → 技术评审+商务谈判 → 合同签订+履约
→ 物料跟踪+到货预警 → 入库+库存管理 → 出库+物料流转 → 成本核算+付款
→ 供应商绩效评估 → 数据报表+决策支持
```

**JD 关键 KPI**（来自采购中心负责人 JD）：
- 采购成本同比下降 12-15%
- 质量提升 20% 以上
- 库存周转天数 15-20 天
- 采购周期 -25%
- 团队协作效率 +30%

**关键观察**：JD 里大量出现"建立 XX 数据库""建立 XX 体系""推动 XX 落地"——**这些"建立"动词暗示了当前的缺失**。

#### OPP-2026-07-01-001 · 紧急采购流程自动化

**基本信息**

| 字段 | 值 |
|---|---|
| 所属中心 | 采购中心（流程节点 [1] 需求接收 + [4] 谈判 + [6] 物料跟踪）|
| 机会类型 | 软件路线 |
| 痛点类型 | 实时性差 + 信息断层 |
| 优先级 | **P0** |
| 价值密度 | ⭐⭐⭐⭐⭐（5.0）|
| 实施成本 | ⭐⭐（2.0）|
| **ROI** | **2.5** |
| 软件可行性 | ⭐⭐⭐⭐⭐（5.0）|

**现状描述**

紧急采购（设备故障备件、客户紧急插单、产线停线物料）是采购中心的高频场景。**当前流程**：
- 需求方口头/电话/微信提单 → 采购员录入 ERP → 找供应商 → 报价审批 → 下单
- **审批链路长**（采购员 → 供应链经理 → CPO 三级，有时还要 CFO）
- **审批工具原始**：邮件、微信、纸质签字
- **现状数字**（待业务方确认）：
  - 频次：每周 5-15 次（紧急采购占总采购 ~20%）
  - 单次耗时：4-8 小时（理想 2 小时可达）
  - 涉及人数：13 个采购员 + 各需求部门主管 + CPO + 财务
  - 拖延后果：产线停线损失（按天计费）/ 客户交期违约

**痛点**

- **审批链路长**：三级审批靠人工跟，紧急时找不到人签字
- **状态不透明**：需求方不知道采购到哪一步，反复问
- **历史数据散落**：紧急采购原因、处理时长无法追溯 → KPI 考核困难
- **结果**：紧急采购平均耗时是常规采购的 2-3 倍，反而更慢

**替代方案**

**目标**：把紧急采购从"4-8 小时"压到"1-2 小时"，状态全流程可追溯。

**技术能力点**：
- **移动审批工作流引擎**：钉钉/企微集成，移动端实时推送审批
- **规则引擎自动判断**：金额/物料类型/紧急程度 → 自动路由到对应审批人
- **可视化看板**：需求方实时看采购进度（订单已发 / 已到货 / 已入库）
- **结构化表单**：需求方填写 → 自动生成采购单 → 推送采购员

**涉及系统/工具**：
- 现有 ERP（用友/金蝶）增强接口
- 钉钉/企微审批（已有）
- 工作流引擎（可基于现有平台扩展）

**关键依赖**：
- 数据：ERP 已有数据 + 紧急采购原因分类（需业务方定义分类标准）
- 接口：ERP ↔ 审批平台 API
- 算力：标准云端足够

**实施周期估计**：3-4 人月（含 1 人月试运行）

**价值估算**

| 维度 | 当前 | 未来 | 节省 |
|---|---|---|---|
| 单次紧急采购耗时 | 4-8 小时 | 1-2 小时 | 3-6 小时 |
| 月度紧急采购次数 | ~40 次 | ~40 次 | — |
| 月度人力节省 | — | — | **120-240 人时** |
| 审批沟通成本 | 高 | 低 | — |
| 状态透明度 | 0（看不见） | 100% | — |

**年化价值估算**：120 人时/月 × 12 = 1440 人时/年 × 平均人力成本 100 元/时 ≈ **14.4 万元/年（直接人力）** + 间接价值（产线不停线、客户不违约）远超直接价值

**实施成本估算**

| 阶段 | 内容 | 人月 |
|---|---|---|
| 需求调研 + 流程梳理 | 紧急采购场景分类、审批权限矩阵 | 0.5 |
| 工作流引擎开发 | 移动审批 + 规则引擎 | 1.5 |
| ERP 接口 | ERP 单据自动生成 | 1 |
| 试运行 + 培训 | 3 个真实场景试运行 + 培训 | 0.5 |
| **合计** | — | **3.5 人月** |

**风险与约束**

- **组织风险**：审批权限矩阵涉及多个部门（CPO / CFO / 需求部门），需要 CEO 层面协调
- **流程风险**：紧急采购的"紧急"判断标准不一，可能被滥用
- **缓解措施**：先在 1-2 个高频场景试点，跑通后扩展

**负责人建议**

- **业务方**：采购中心负责人（CPO）+ 供应链管理经理
- **承接方**：行政运营中心信息化组（软件路线）
- **协助**：各需求部门主管（装备研发 / 电池研发 / 生产交付）

#### OPP-2026-07-01-002 · 需求结构化与自动派单

**基本信息**

| 字段 | 值 |
|---|---|
| 所属中心 | 采购中心（流程节点 [1] 需求接收）|
| 机会类型 | **双路并行**（AI 路线 + 软件路线）|
| 痛点类型 | 信息断层 + 高频重复 |
| 优先级 | **P0** |
| 价值密度 | ⭐⭐⭐⭐⭐（5.0）|
| 实施成本 | ⭐⭐⭐（3.0）|
| **ROI** | **1.67** |
| AI 可行性 | ⭐⭐⭐⭐⭐（5.0）|
| 软件可行性 | ⭐⭐⭐⭐（4.0）|

**现状描述**

需求部门（装备研发 / 电池研发 / 产线策划 / 生产交付）给采购的需求**绝大多数是口语化描述**：
- "我需要一批电机，参考 XX 那个设备的规格"
- "上次买的 XX 试剂，再来 10 瓶"
- "客户定制一台设备，电机要防爆的"

采购员要花大量时间**翻译、追问、确认规格**。**现状数字**（待业务方确认）：
- 频次：每天 10-30 次需求接收
- 单次翻译耗时：0.5-2 小时
- 涉及人数：13 个采购员 + 30+ 需求方
- 反复追问率：>50% 的需求至少追问一次

**痛点**

- **信息断层**：需求从"人话"到"采购单"的转换靠人脑
- **反复对齐**：采购员和需求方来回沟通，浪费时间
- **规格不统一**：同样的物料不同人提的需求格式不一，难比对
- **历史需求散落**：Excel/邮件/微信群里，没有结构化数据库

**替代方案**

**方案 1（推荐）：AI 路线 + 软件路线双路并行**

- **AI 路线（LLM 需求结构化）**：
  - 需求方用自然语言提单（钉钉/企微机器人对话）
  - LLM 自动抽取：物料类型 / 规格 / 数量 / 紧急程度 / 预算 / 期望交付日期
  - 与历史采购库匹配：识别"上次买的同款"，自动填入参考规格
  - 不确定的字段反问需求方（带建议）

- **软件路线（采购工单系统）**：
  - 结构化表单：必填字段约束（物料类型 / 规格 / 数量 / 用途）
  - 模板库：常用物料类型预设模板（电机 / 试剂 / 标准件 / 定制件）
  - 自动派单：根据物料类型自动派给对应采购员（如"实验试剂"→ 技术采购专家，"定制件"→ 供应链经理）
  - 工单状态跟踪：采购员和需求方都能看进度

**方案 2（备选）：纯软件路线（无 AI）**

- 仅做结构化表单 + 模板库，无 LLM 结构化抽取
- 优点：实施快、成本低
- 缺点：需求方填写负担增加（必须自己填全字段）

**价值估算**

| 维度 | 当前 | 未来（双路并行）| 节省 |
|---|---|---|---|
| 单次需求接收耗时 | 0.5-2 小时 | 5-10 分钟 | 80-90% |
| 反复追问率 | >50% | <10% | 80% |
| 月度需求次数 | ~300 次 | ~300 次 | — |
| 月度人力节省 | — | — | **200-400 人时** |

**年化价值估算**：300 人时/月 × 12 = 3600 人时/年 × 100 元 ≈ **36 万元/年（直接人力）** + 间接价值（采购响应更快 → 研发/生产不被卡）

**实施成本估算**

| 阶段 | 内容 | 人月 |
|---|---|---|
| 需求模板设计 + 字段标准 | 联合 4-5 个需求部门梳理 | 1 |
| LLM 应用开发 | 钉钉/企微机器人 + RAG（历史采购库）| 2 |
| 采购工单系统开发 | 表单 + 派单规则 + 状态跟踪 | 2 |
| 集成（ERP + IM）| API 对接 | 1 |
| 试运行 + 培训 | 试点 1 个部门 → 扩展 | 1 |
| **合计** | — | **7 人月** |

**风险与约束**

- **LLM 幻觉风险**：LLM 可能误判规格 → 缓解：关键字段必须人工二次确认
- **历史数据准备**：需要历史采购数据清洗（Excel/邮件），约 2-3 个月积累
- **工艺机密**：涉及装备规格/电池材料 → 私有化部署 + 权限控制

**负责人建议**

- **业务方**：采购中心（CPO）+ 各需求部门主管
- **AI 路线承接**：AI 3D 事业中心（LLM 应用组）
- **软件路线承接**：行政运营中心信息化组
- **协调**：PMOC（跨部门协同）

#### OPP-2026-07-01-003 · 物料齐套与缺料智能预警

**基本信息**

| 字段 | 值 |
|---|---|
| 所属中心 | 采购中心（流程节点 [6] 物料跟踪 + [7] 入库）|
| 机会类型 | **双路并行**（AI 路线 + 软件路线）|
| 痛点类型 | 实时性差 + 信息断层 |
| 优先级 | **P0** |
| 价值密度 | ⭐⭐⭐⭐⭐（5.0）|
| 实施成本 | ⭐⭐⭐（3.0）|
| **ROI** | **1.67** |
| AI 可行性 | ⭐⭐⭐⭐（4.0）|
| 软件可行性 | ⭐⭐⭐⭐⭐（5.0）|

**现状描述**

生产交付中心按订单装配设备时，物料齐套检查**完全靠人工**：
- 仓库管理员按 BOM 逐项核对（每个设备 50-200 项物料）
- 缺料时通知采购员跟催
- 采购员再联系供应商确认交期
- **整条链路反馈慢**，经常出现"装配到一半发现缺料"

**现状数字**（待业务方确认）：
- 频次：每个设备装配 1 次齐套检查（共 21 人 × ~10 设备/月 = ~100 次/月）
- 单次齐套检查耗时：2-4 小时
- 缺料发生率：~15-25%（业内常见）
- 缺料导致的装配停线：每月 3-5 次

**痛点**

- **实时性差**：缺料发现滞后 → 装配停线损失
- **跟催链路长**：仓库 → 采购员 → 供应商 → 采购员 → 仓库
- **预测能力弱**：无法预测"未来 N 天哪些物料可能缺"
- **跨部门协同成本**：生产交付 + 采购 + 供应商三方沟通成本高

**替代方案**

**方案 1（推荐）：双路并行**

- **软件路线（实时齐套看板）**：
  - ERP + WMS 实时数据集成
  - 按 BOM 自动计算齐套率（已入库 / 应入库）
  - 大屏看板：每个订单的齐套状态、缺料项、预计到货时间
  - 移动推送：缺料预警自动推送给采购员和装配班长

- **AI 路线（缺料预测 + 智能跟催）**：
  - 基于历史数据训练模型：哪些物料经常缺、缺料前有哪些信号（供应商交期延误 / 用量超预期）
  - 提前 N 天预警："这批物料可能在 X 月 X 日前到不了，建议加急或换供应商"
  - 智能跟催话术：根据供应商历史响应模式，自动生成跟催话术
  - 缺料根因分析：每月自动生成"缺料 Top 5 原因"

**价值估算**

| 维度 | 当前 | 未来 | 节省 |
|---|---|---|---|
| 单次齐套检查 | 2-4 小时 | 0.5-1 小时 | 75% |
| 缺料发现到响应 | 4-8 小时 | 30 分钟 - 1 小时 | 90% |
| 月度装配停线次数 | 3-5 次 | 1-2 次 | 60% |
| 停线损失 | X 万元/月 | X/3 万元/月 | ~60% |

**年化价值估算**：直接人力节省约 **15-20 万元/年** + 停线损失节省（按 21 人 × 装配工资 + 客户违约成本，可能 **50-100 万元/年**）

**实施成本估算**

| 阶段 | 内容 | 人月 |
|---|---|---|
| ERP/WMS 数据集成 | 实时库存 + BOM 数据打通 | 2 |
| 齐套看板开发 | 大屏 + 移动端 | 1.5 |
| AI 缺料预测模型 | 历史数据 + 供应商数据 | 2 |
| 智能跟催 + 根因分析 | LLM 应用 | 1.5 |
| 试运行 + 培训 | 跨部门协同（生产 + 采购）| 1 |
| **合计** | — | **8 人月** |

**风险与约束**

- **数据集成复杂度**：ERP + WMS + 钉钉/企微多系统集成，需要架构设计
- **预测模型冷启动**：需要 3-6 个月历史数据积累
- **跨部门协同**：生产交付中心需配合使用看板

**负责人建议**

- **业务方**：采购中心（供应链管理经理 + 仓库管理员）+ 生产交付中心
- **AI 路线承接**：AI 3D 事业中心（数据分析组 + LLM 应用组）
- **软件路线承接**：行政运营中心信息化组（数据中台组）

#### OPP-2026-07-01-004 · 供应商智能匹配与分级管理

**基本信息**

| 字段 | 值 |
|---|---|
| 所属中心 | 采购中心（流程节点 [2] 供应商匹配/寻源 + [10] 供应商绩效）|
| 机会类型 | 软件路线 + AI 增强 |
| 痛点类型 | 经验依赖 + 信息断层 |
| 优先级 | **P0** |
| 价值密度 | ⭐⭐⭐⭐（4.5）|
| 实施成本 | ⭐⭐⭐（3.0）|
| **ROI** | **1.5** |
| AI 可行性 | ⭐⭐⭐⭐（4.0）|
| 软件可行性 | ⭐⭐⭐⭐（4.0）|

**现状描述**

采购中心有 3 级供应商体系（战略 / 核心 / 备选），但**供应商信息分散**：
- 分级：靠采购员脑子 + Excel
- 价格：分散在 Excel 和邮件
- 绩效：评估靠主观打分（每季度/年度）
- 历史合作：信息在采购员个人手里，**人员流动时信息丢失**

**现状数字**（待业务方确认）：
- 供应商总数：~50-100 家（待确认）
- 询价匹配耗时：每次 0.5-2 小时（找供应商、查历史价格、对比）
- 询价频次：每周 10-20 次
- 战略供应商：~10 家（待确认）

**痛点**

- **经验依赖**：新采购员需要老员工带 6 个月以上才能独立询价
- **信息分散**：供应商信息散落在个人 Excel / 邮件 / 微信
- **绩效主观**：评估靠打分表，容易"老好人"或"凭印象"
- **寻源效率低**：开发新供应商靠关系 / 展会，效率低

**替代方案**

**方案 1（推荐）：软件路线（SRM 系统）+ AI 增强**

- **SRM（供应商关系管理）系统**：
  - 供应商主数据：统一管理供应商档案（资质、联系人、历史合作）
  - 三级分级：战略 / 核心 / 备选，明确准入 / 升级 / 降级规则
  - 价格库：物料 → 历史价格曲线 → 自动比价
  - 绩效评分：基于 ERP 数据自动计算（交付率 / 质量合格率 / 价格波动）

- **AI 增强（智能匹配 + 寻源推荐）**：
  - 智能匹配：需求来了 → 自动推荐 Top 3 供应商（基于历史合作 + 价格 + 交付）
  - 新供应商寻源：基于行业知识图谱 + 公开数据，推荐潜在供应商
  - 风险预警：供应商资质到期 / 财务异常 / 行业风险

**价值估算**

| 维度 | 当前 | 未来 | 节省 |
|---|---|---|---|
| 询价匹配耗时 | 0.5-2 小时 | 5-15 分钟 | 80-90% |
| 新人上手周期 | 6 个月 | 1-2 个月 | 70% |
| 供应商绩效评估 | 主观打分 | 自动计算 + 主观补充 | 50% 时间节省 |

**年化价值估算**：13 个采购员 × 平均 30 分钟/天 节省 = 65 人时/天 × 250 天 ≈ **1600 人时/年 × 100 元 ≈ 16 万元/年**

**实施成本估算**

| 阶段 | 内容 | 人月 |
|---|---|---|
| SRM 系统选型 + 实施 | 商业产品（如用友 SRM）或自研 | 3-6 |
| 供应商主数据清洗 | 历史供应商信息结构化 | 2 |
| AI 智能匹配 + 寻源推荐 | LLM + 知识图谱 | 3 |
| 试运行 + 培训 | 全采购团队 | 1 |
| **合计** | — | **9-12 人月** |

**风险与约束**

- **SRM 选型**：商业产品成熟但贵（年费 ~10-30 万），自研灵活但慢
- **数据清洗工作量大**：历史供应商数据散落 5+ 年，需要专门团队
- **组织接受度**：老采购员可能抵触"系统替代经验"

**负责人建议**

- **业务方**：采购中心负责人（CPO）+ 供应链管理经理
- **承接方**：行政运营中心信息化组（主导）+ AI 3D 事业中心（AI 模块）
