# AI 机会清单 — 轻量快速胜利版

> **专门写给"想先出点成绩"的同事**
>
> 上一份清单（59 个机会）适合"想搞大事"的人看，但对你来说太重。这份是从那 59 个里**挑出来最轻的 8 个**，专门为这种场景设计：
> - 想 1-2 季度内出成果，给领导看到东西
> - 不敢搞砸 / 不能搞砸
> - 资源有限，没有大团队、没有大预算
> - 需要快速建立信任，再去做更大的事

---

## 筛选标准（什么算"简单"）

| 标准 | 说明 |
|---|---|
| **实施周期 ≤ 4 人月** | 1-2 季度能上线 |
| **不依赖跨中心协调** | 一个部门内能搞定，不需要 CEO 拍板 |
| **数据已有或容易整理** | 不需要大规模数据治理 |
| **技术成熟** | 用现成 SaaS / 工具能跑通，不需要训练 AI 模型 |
| **失败风险低** | 就算效果一般，也不会出大问题 |
| **见效快** | 上线 1-2 个月内能看到效果 |

## 一、自己一个人能搞定的（无需 IT 团队）

> **门槛最低**：用现成的 SaaS / LLM 工具，自己就能跑通 POC。适合先出个 demo 给领导看。

### 机会 1 · 实验报告 / 工艺方案 AI 自动生成（⭐⭐⭐⭐⭐ 推荐第一）

| 项 | 内容 |
|---|---|
| **中心** | 电池研发中心 |
| **实施周期** | 2-3 个月（含 POC 1 个月 + 推广 1-2 个月）|
| **难度** | ⭐ 极简 |
| **见效时间** | POC 当周就能给领导演示 |
| **ROI** | ⭐⭐⭐⭐⭐（1.8，最高之一）|

**为什么简单**：
- 你只需要一个 LLM 账号（公司如果订阅了 ChatGPT/Claude/Gemini，直接用就行）
- 拿 5-10 份历史实验报告做模板，让 LLM 学会格式
- 工程师下次写报告时，丢原始数据给 LLM，让它按模板生成初稿
- **不需要任何系统集成**，就是个 Prompt 工程 + Word 模板

**你能怎么做（具体步骤）**：
1. 找 3-5 份典型的电池实验报告（PDF/Word）
2. 用 ChatGPT/Claude 写一个 Prompt："你是电池研发工程师，根据下面的实验数据，按这份报告模板生成报告"
3. 把 Prompt + 模板给电池研发中心负责人试用
4. 收集反馈，调整 Prompt
5. 做成"实验报告生成器"小工具（甚至就是个填表网页）

**给领导汇报怎么说**：
> "电池研发工程师每月写 30-50 份实验报告，每份 2-4 小时。我用 LLM 工具做了 POC，1 份报告能省 1-2 小时。**一个月能省 30-50 个工时 = 一个全职人力**。接下来我想推动做成标准化工具，全公司推广。"

**价值估算**：月节省 30-50 工时 × 12 × 100 元/工时 = **3.6-6 万元/年**（直接人力）+ 间接价值（报告质量提升、电池工程师专注实验）

| 项 | 内容 |
|---|---|
| **中心** | 产线策划设计中心（或任何中心）|
| **实施周期** | 1-2 周就能跑 |
| **难度** | ⭐ 极简 |
| **见效时间** | 立即 |
| **ROI** | ⭐⭐⭐（中，但成本极低）|

**为什么简单**：
- 产线策划负责人 JD 提到"跟踪行业技术趋势"——当前靠人工订阅期刊+展会
- 用 LLM 自动跟踪：给它行业关键词，让它每天/每周自动生成摘要

**你能怎么做**：
1. 列出 10-20 个行业关键词（固态电池 / 干法电极 / 全极耳 / 锂硫电池 等）
2. 用 ChatGPT/Claude 写一个 Agent："每周搜一次这些关键词的最新进展，输出 1 页摘要"
3. 配上 RSS 订阅 / 简单爬虫（甚至手工转发也行）
4. 每周自动出一份"行业动态周报"

**给领导汇报怎么说**：
> "我们跟踪行业动态靠人工订阅期刊和展会，信息分散。我做了一个 LLM 自动化工具，每周自动出一份行业动态周报，**信息覆盖 5 倍以上，研究员每周节省 4-5 小时**。"

**价值**：研究员每周节省 4-5 小时；信息覆盖度大幅提升

### 机会 4 · 紧急采购流程自动化（⭐⭐⭐⭐⭐ 推荐第二）

| 项 | 内容 |
|---|---|
| **中心** | 采购中心 |
| **实施周期** | 3-4 人月（其中 1 人月可先跑 POC）|
| **难度** | ⭐⭐ 中等简单 |
| **见效时间** | POC 1 个月内 |
| **ROI** | ⭐⭐⭐⭐⭐（2.5，**所有机会里最高**）|

**为什么简单**：
- 不需要写新系统，**直接用钉钉/企微的审批流**就能做
- 紧急采购场景固定（紧急程度+金额+物料类型），规则明确
- **第 1 步就能跑通 80%**：把现有"邮件+微信+纸质"的审批搬到钉钉/企微

**你能怎么做（最小启动版）**：
1. **第 1 周**：找 CPO / 供应链经理聊，画出当前紧急采购的流程图（哪几步、谁审批、平均耗时）
2. **第 2-3 周**：在钉钉/企微搭一个"紧急采购申请"审批流（10 个表单字段 + 3 级审批）
3. **第 4 周**：找 2-3 个真实紧急采购场景试用，收集反馈
4. **第 2 个月**：跑通后让采购中心全员切换
5. **第 3-4 个月**：加移动端推送 + 状态看板

**不需要的**：
- ❌ 不需要 AI（这就是个工作流）
- ❌ 不需要复杂 ERP 集成（先用表单跑通，后续再考虑对接）
- ❌ 不需要写代码（钉钉/企微自带的低代码就能搭）

**给领导汇报怎么说**：
> "紧急采购目前靠邮件+微信+纸质审批，平均要 4-8 小时，**经常找不到人签字**。我用钉钉审批搭了个 POC，把流程搬到线上，**目标压到 1-2 小时，状态全流程可追溯**。先把 1 个采购小组用起来，跑通后全员推广。"

**价值**：每次紧急采购节省 3-6 小时；月节省 ~150 工时；产线停线风险下降

### 机会 5 · 供应商绩效自动评分

| 项 | 内容 |
|---|---|
| **中心** | 采购中心 |
| **实施周期** | 3-4 人月 |
| **难度** | ⭐⭐ 中等简单 |
| **见效时间** | 1 个月出第一版评分 |
| **ROI** | ⭐⭐⭐（中，但持续价值高）|

**为什么简单**：
- 评分规则明确（交付率 / 质量合格率 / 价格波动 / 服务响应）
- 数据来源是 ERP（已经有了）
- 不需要 AI，用 Excel + 简单脚本就能跑

**你能怎么做**：
1. **第 1 周**：定义评分公式（和供应链经理一起定）
2. **第 2-3 周**：从 ERP 导出供应商基础数据（订单/到货/质量/价格），用 Excel/脚本算分
3. **第 4 周**：自动生成月度评分表
4. **第 2-3 个月**：做成简单网页（IT 同事帮做），采购员可查询可下载

**给领导汇报怎么说**：
> "供应商绩效评估靠 Excel 主观打分，**评估周期长、标准不统一**。我做了一个自动评分工具，基于 ERP 数据自动算分，**评估周期从月→周，主观打分占比从 100%→30%**。"

| 🥈 **2** | **机会 1 · 实验报告 AI 自动生成** | ⭐ 极简 | POC 当周 | ROI 最高，电池研发负责人容易认可 |

**组合打法**：
- **第 1-2 周**：先做机会 2（行业跟踪），给领导演示——"我做出了 AI 应用"

这样**3 个月里有 3 次成果汇报**，领导会看到你**持续在推进**，而不是"提了一堆方案没动静"。

## 怎么向领导汇报（3 步法）

### 第 1 步：先讲痛点，不讲方案

> ❌ 错误："我做了个 AI 系统..."
> ✅ 正确："我发现我们 XX 部门每个月浪费 X 个小时在 XX 工作上..."

**开场模板**：
> "领导，我最近在做业务流程梳理，发现几个**我们部门能立刻动手、风险很低、见效很快**的机会。今天先汇报 3 个。"

### 第 2 步：先讲 ROI，不讲技术

> ❌ 错误："我用 LLM + RAG + Agent..."
> ✅ 正确："这个项目投入 2 个人月，**3 个月内能省 X 人天 / 降 X% 错误率**"

**核心数字模板**：
- 投入：X 人月 / X 万预算
- 产出：年节省 X 万元 / X 工时
- 风险：低（用的是成熟技术，不需要大改）

### 第 3 步：先要资源，不要求认可

> ❌ 错误："您觉得这个方案怎么样？"
> ✅ 正确："我需要 X 个 IT 同事支持 X 周 + 业务部门 X 同事每周 X 小时配合。"

**结尾模板**：
> "我想先用 2 周做个 POC 给您看效果。**需要 IT 同事张三人天 + 业务部门李四每周 2 小时配合**。可以推进吗？"
