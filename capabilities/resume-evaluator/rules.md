# 简历评价规则（resume-evaluator）

> 输入：一份候选人简历 + 一个**已收口的岗位画像**（reasoning 拆出的核心/加分能力）。
> 输出：一份岗位匹配度报告（分数 + 推荐等级 + 逐项印证 + 风险提示），按 `report-template.md` 输出。
> 本文定义"画像能力 → 评分项 → 评分"的映射与评分策略。
>
> **通用性说明**：本规则是**岗位无关的方法论**。评分项不是固定的，而是从**每个岗位的画像**里来——
> 换任何岗位（采购/工程师/质量/研发…），只要先有画像，评分项就自动生成，本规则照跑。

---

## 一、核心原则（三条，从岗位拆解铁律继承）

1. **每给一分都挂简历原文。** 不许出现没有出处的分数。打几分，后面必须跟 `[印证："简历原话/事迹"]`。
2. **"没写" ≠ "没有"，不许直接扣死。** 简历没体现的能力，一律进【风险提示】+【面试重点】，让面试去验，不靠猜扣分。
   - 唯一例外：**门槛项**（见第三节）——学历/经验这类有客观答案的，简历没写=缺失，按门槛规则扣。
3. **区分"有细节"和"提了一嘴"。** 只写"负责采购"= 1分；写了具体场景/做法/成果= 2~4分。模糊自述不能高分。

---

## 二、评分框架（三层，通用）

| 层 | 内容 | 权重区间 | 性质 |
|---|---|---|---|
| **门槛项** | 学历 / 工作年限 / 专业 / 行业背景 | — | **软门槛**（见用户决策③）：高权重，不达标重扣，但"特别优秀"可豁免 |
| **核心能力** | 画像【核心能力·必须】的每一条（逐条转评分项） | **合计 60–70%** | 主导总分 |
| **加分能力** | 画像【加分能力·锦上添花】的每一条 | **合计 15–30%** | 拉开梯队，不卡门槛 |

> 权重区间是"自适应"的：核心条目多的岗位，核心占比取高值；加分条目多的，加分占比取高值，但**核心永远 > 加分**。

**默认权重分配（每份画像生成评分表时按此套，除非用户指定）：**

```
门槛项        20%   （其中：学历 10% / 经验+行业 10%）
核心能力合计  65%   （各条核心能力均分这 65%）
加分能力合计  15%   （各条加分能力均分这 15%）
─────
合计         100%
```

---

## 三、门槛项规则（软门槛，2026-06-24 用户决策③）

**学历/经验这类有客观答案的项，不进 0–4 量表，按"达标/不达标"判定，再换算成权重分。**

| 判定 | 学历 | 处理 |
|---|---|---|
| ✅ 达标 | 等于或高于 JD 要求（如 JD 要本科，候选人是本科及以上） | 该项满分 |
| ⚠️ 略低 | 略低于要求但可能可补（如专科，但经验足） | 该项 30–50% 分，**进【风险提示】**，需面试验 |
| ❌ 明显不符 | 明显低于要求且无补偿 | 该项 0 分 |
| 🌟 豁免 | 学历不足，但核心能力评分极高（见"豁免机制"） | 该项按满分计入，并在报告中**显式标注"学历豁免"** |

**豁免机制（"特别优秀"如何界定，避免主观）：**
- 当候选人**核心能力合计分 ≥ 90% 满分**（即 4 项核心里大多数拿到 3~4 分且挂强证据），
- **且** 加分能力中有 2 项以上拿到 2 分及以上（说明在该领域有可见积累），
- 则触发学历豁免：学历项按满分计入，报告标注 `[🌟学历豁免：核心能力评分极高，建议破格]`。
- **豁免是例外不是常态**——必须严格满足上面两个量化条件，不许凭感觉放水。

**经验/行业背景同理**（按 JD 要求判定达标/略低/不符），但不设豁免（经验不足难靠"优秀"补，只能面试验）。

---

## 四、0–4 量表（核心 & 加分能力通用）

对画像里每一条核心/加分能力，按候选人在简历中的体现打 0–4 分：

| 分 | 含义 | 典型简历信号 |
|---|---|---|
| **0** | **无证据** | 简历完全没提该项能力 |
| **1** | **提及但无细节** | 只有一句话自述（如"负责采购工作"），看不出怎么做的 |
| **2** | **有场景/有细节** | 写了具体做的事、涉及的对象（如"负责机加工件下单到入库全流程"） |
| **3** | **有做法/有案例** | 能看出怎么做的（如"主导供应商谈判，建立分级评估体系"） |
| **4** | **有量化成果** | 有数字（如"年度降本 12%、交期缩短至 20 天"）——最强 |

**评分必须挂印证**：每一项后面跟 `[印证："简历原话或事迹概述"]`。
- 0 分标 `[印证：简历未提及]`，并自动进【风险提示】。
- 引用尽量用简历**原话或近义转述**，加引号，便于你复核。

---

## 五、算分公式

**单条能力得分** = （该条 0–4 分 / 4）× 该条权重

**总分** = 门槛项小计 + 各核心能力小计 + 各加分能力小计（满分 100）

**推荐等级映射（总分 → 等级）：**

| 总分 | 推荐等级 | 含义 |
|---|---|---|
| **≥ 85** | **A 强推** | 核心能力扎实、多数有量化，可直接推进面试 |
| **70–84** | **B 可面** | 核心够用、有缺口，值得面试深挖 |
| **55–69** | **C 谨慎** | 缺口较多或门槛不达标，面试需重点验疑点 |
| **< 55** | **D 不推荐** | 核心能力大面积无证据或门槛硬伤 |

> ⚠️ **等级不是总分唯一决定**——若**核心能力有任何一条得 0 分**（关键职能完全无证据），即便总分够，等级**最多给 B**，并在报告中红色提示"关键能力缺失，需面试重点验"。这是为了防止"靠加分项凑分掩盖核心空洞"。

---

## 六、报告输出（按 `report-template.md`）

固定结构：
1. **匹配度分数 + 推荐等级**（一句话结论）
2. **门槛项**判定表（学历/经验/行业，逐项标✅⚠️❌🌟）
3. **核心能力**逐项（0–4分 + 权重 + 印证原话）
4. **加分能力**逐项（同上）
5. **算分明细**（权重表，透明可复核）
6. **风险提示**（"没写≠没有"的项 + 门槛略低项，待面试验证）
7. **面试重点**（从风险里挑 2–3 个最该问的）

---

## 七、评分流程（agent 执行顺序）

1. **拿到画像**：确认已有该岗位的收口画像（核心能力 N 条 / 加分能力 M 条 / JD 门槛要求）。
   - 没有画像 → **不直接评分**，先走 reasoning 拆出画像，或请用户提供/确认画像。
2. **生成评分表**：把画像的核心/加分能力**逐条转成评分项**，按第二节默认权重分配（或用户指定权重）。
3. **逐项读简历打分**：对每条评分项，在简历里找证据 → 打 0–4 分 → 挂印证原话。
   - 找不到证据 → 0 分 + 进风险提示。
4. **判门槛项**：学历/经验按 JD 要求判达标/略低/不符，检查是否触发学历豁免。
5. **算总分 + 定等级**：按第五节公式。注意"核心有 0 分则等级封顶 B"的保护规则。
6. **写报告**：按 `report-template.md`，存到 `output/`（命名见第八节）。
7. **向用户报告**：分数 + 等级 + 最关键的 2–3 条风险/面试重点（口语化摘要，细节看报告文件）。

---

## 八、文件命名与存储

- **目录**：`output/`（与 JD 共用，**唯一可写**）
- **命名**：`{{岗位名称}}-简历评估-{{候选人姓名或编号}}-{{YYYY-MM-DD}}.md`
  - 例：`定制件采购工程师-简历评估-张三-2026-06-24.md`
- **禁止**：
  - ❌ **绝不修改 `岗位职责说明书/` 下任何原文件**（只读参考源）
  - ❌ 不覆盖 `output/` 同名文件（同名加序号 `-2`、`-3`）

## 九、与主流程的关系

resume-evaluator 是**独立模块**（"量尺"），被 reasoning（"大脑"）在画像收口后、收到简历时调用：

```
用户给简历 → reasoning 确认有对应画像 → 【调用 resume-evaluator】
           → 画像能力转评分项 → 逐项打分 → 算总分定等级 → 产出报告到 output/
```

**解耦关系：**
- 改评分方法论/量表 → 只动 `rules.md`（本文）
- 改报告格式 → 只动 `report-template.md`
- 改岗位画像（核心/加分能力） → 走 `reasoning-rules.md`，评分项自动跟着变
- 三者互不影响。

**与 jd-generator 平级**：两个独立模块共用 reasoning 的画像产出。
- jd-generator = "打印机"（画像 → JD 文件）
- resume-evaluator = "量尺"（画像 + 简历 → 匹配度报告）

## 十、边界（不做的事）

- ❌ 不评价候选人的"性格/文化契合度"等画像外维度——只评画像里有的能力。
- ❌ 不替用户做最终录用决定——只给匹配度 + 风险，决策权在人。
- ❌ 不凭通用招聘知识编造评分项——每项必须来自该岗位画像，画像没有的能力不打分。
- ❌ 不在简历信息不足时硬评——简历过于简略（如只有姓名岗位），先请用户补料或标"信息不足，建议补简历"。
- ✅ 简历与画像"错位"时要提示（如给的是销售简历，画像是采购岗）——提醒用户岗位不匹配，问是否仍要评。
